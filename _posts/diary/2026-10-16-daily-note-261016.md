백엔드 개발자, 프론트엔드 개발자처럼 애플리케이션을 만들고 유지보수하는 일은 이제 AI가 사람보다 훨씬 빠르고, 비용도 적게 들 것 같다.

그래서 앞으로는 이런 개별 능력치보다, **기획·개발·유지보수로 이어지는 업무 흐름 전체를 AI-네이티브하게 설계하고, 그게 실제로 돌아가게 만드는 역할**이 훨씬 더 중요해질 것 같다는 생각이 든다.

돌이켜보면 지금까지 '유지보수하기 좋은 코드', '확장성 좋은 코드'의 기준은 전부 **사람의 관점**이었다. <br>
사람이 읽기 쉽고, 사람이 고치기 쉬운 코드. <br>
이제는 같은 질문을 **AI의 관점**에서 다시 던져봐야 하는 시점인 것 같다.

결국 중요한 건 이런 것들이 아닐까 싶다.

- 비즈니스를 깊이 이해하는 것
  - 코드에 녹아 있는 비즈니스 로직 수준이 아니라, **사업이 어떻게 굴러가고 어디서 임팩트를 낼 수 있는지**에 대한 이해
- AI 에이전트가 어떻게 동작하는지 잘 이해하는 것
- 그래서 AI가 **의도한 대로** 동작하도록 만드는 것

물론 아직까지 내가 경험한 바로는, 최종적으로 책임지는 건 사람의 몫이다. 그래서 사람이 개입해야 할 부분도 여전히 많다. <br>
하지만 언젠가는 **AI가 책임지고 사람이 보조하는 구조**가 더 효율적인 날이 올 수도 있겠다는 생각도 든다.

실제로 이런 방향의 채용 공고도 보인다. OpenAI의 [Software Engineer, API Agents](https://jobs.ashbyhq.com/openai/a6ab3111-7092-4da2-a7a6-71e01351bfda) 공고(2026-10-16 기준)에서는 팀을 이렇게 소개한다.

> API Agents builds the shared agent harness, tools, and infrastructure that turn OpenAI’s frontier models into systems that can **reliably complete real work**. <br>
> (모델을 **실제 업무를 안정적으로 끝내는 시스템**으로 만드는 에이전트 하네스·도구·인프라를 만든다.)

역할에 대해서는 이렇게 쓰여 있다.

> This is software and systems engineering rather than model training: success comes from strong backend fundamentals, high agency, and the ability to **turn fast-moving research capabilities into dependable production primitives**. <br>
> (모델 학습이 아니라 소프트웨어·시스템 엔지니어링이다. 빠르게 발전하는 AI 역량을 **믿고 쓸 수 있는 프로덕션 기반으로 바꾸는 능력**이 핵심이다.)

결국 AI가 '일을 할 수 있게' 만드는 판을 깔고, 그게 의도대로 굴러가게 하는 것. 위에서 말한 방향과 맞닿아 있다고 느꼈다.
