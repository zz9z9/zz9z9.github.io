
## HashMap
**리사이징**
- 해시 테이블의 크기가 작아지면 해시값을 저장할 수 있는 버킷(bucket)의 개수도 줄어들어 충돌 가능성이 높아진다.
- 인덱스 계산 : `(n - 1) & hash` -> `(hash % n)`과 동일
  - n은 테이블 사이즈

| 키 값 | 해시값 (가정) | 테이블 크기=5 (`hash % 5`) | 테이블 크기=10 (`hash % 10`) |
| --- | --- | --- | --- |
| `A` | `123` | `123 % 5 = 3` | `123 % 10 = 3` |
| `B` | `98` | `98 % 5 = 3` | `98 % 10 = 8` |
| `C` | `45` | `45 % 5 = 0` | `45 % 10 = 5` |
| `D` | `78` | `78 % 5 = 3` | `78 % 10 = 8` |

- 테이블 크기 = 5인 경우, A, B, D가 같은 인덱스(3)에 충돌함.
- 테이블 크기 = 10인 경우, B와 D가 각각 8번 인덱스로 분산되어 충돌이 줄어듦.
- 이처럼 해시 테이블의 크기가 커지면 인덱스의 개수가 증가하여 충돌 가능성이 낮아집니다.

**트리 변환 과정**
- 현재 해시 테이블(tab)의 크기가 너무 작으면(MIN_TREEIFY_CAPACITY(64) 미만) 트리 변환 대신 리사이징(resize()) 수행.
- 트리 변환이 필요하면 연결 리스트의 모든 요소를 TreeNode로 변환.
- 변환된 TreeNode를 레드-블랙 트리 구조로 정렬(treeify())하여 최적화된 검색 속도(O(log N))를 제공.

**레드-블랙 트리 ?**
- Red-Black Tree는 이진 검색 트리(Binary Search Tree, BST)의 한 종류로, 균형을 유지하면서 삽입, 삭제, 검색이 O(log N)을 보장합니다.
- 일반적인 **이진 검색 트리(BST)**는 불균형할 가능성이 높아 최악의 경우 O(N)이 될 수 있음.
- Red-Black Tree는 **균형을 자동으로 유지**하므로 **검색, 삽입, 삭제 연산이 항상 O(log N)**에 수렴.
- 따라서 해시 충돌이 많아지더라도, 트리로 변환하면 성능 저하를 막을 수 있음.

## ConcurrentHashMap
- 버킷 단위로 synchronized 잡는다

```java
transient volatile Node<K,V>[] table;

final V putVal(K key, V value, boolean onlyIfAbsent) {
    if (key == null || value == null) throw new NullPointerException();
    int hash = spread(key.hashCode());
    int binCount = 0;
    for (Node<K,V>[] tab = table;;) {
        Node<K,V> f; int n, i, fh; K fk; V fv;
        if (tab == null || (n = tab.length) == 0)
            tab = initTable();
        else if ((f = tabAt(tab, i = (n - 1) & hash)) == null) {
            if (casTabAt(tab, i, null, new Node<K,V>(hash, key, value)))
                break;                   // no lock when adding to empty bin
        }
        else if ((fh = f.hash) == MOVED)
            tab = helpTransfer(tab, f);
        else if (onlyIfAbsent // check first node without acquiring lock
                 && fh == hash
                 && ((fk = f.key) == key || (fk != null && key.equals(fk)))
                 && (fv = f.val) != null)
            return fv;
        else {
            V oldVal = null;
            synchronized (f) {
                if (tabAt(tab, i) == f) {
                    if (fh >= 0) {
                        binCount = 1;
                        for (Node<K,V> e = f;; ++binCount) {
                            K ek;
                            if (e.hash == hash &&
                                ((ek = e.key) == key ||
                                 (ek != null && key.equals(ek)))) {
                                oldVal = e.val;
                                if (!onlyIfAbsent)
                                    e.val = value;
                                break;
                            }
                            Node<K,V> pred = e;
                            if ((e = e.next) == null) {
                                pred.next = new Node<K,V>(hash, key, value);
                                break;
                            }
                        }
                    }
                    else if (f instanceof TreeBin) {
                        Node<K,V> p;
                        binCount = 2;
                        if ((p = ((TreeBin<K,V>)f).putTreeVal(hash, key,
                                                       value)) != null) {
                            oldVal = p.val;
                            if (!onlyIfAbsent)
                                p.val = value;
                        }
                    }
                    else if (f instanceof ReservationNode)
                        throw new IllegalStateException("Recursive update");
                }
            }
            if (binCount != 0) {
                if (binCount >= TREEIFY_THRESHOLD)
                    treeifyBin(tab, i);
                if (oldVal != null)
                    return oldVal;
                break;
            }
        }
    }
    addCount(1L, binCount);
    return null;
}
```

## ArrayList vs LinkedList vs 배열

| 특성 | 배열 (`Array`) | `ArrayList` | `LinkedList` |
| --- | --- | --- | --- |
| **크기 조절** | 불가능 | 가능 (자동 증가) | 가능 (동적 노드 추가) |
| **메모리 사용량** | 낮음 | 중간 (배열 크기 증가 시 오버헤드) | 높음 (노드마다 참조 필요) |ㅁ
| **랜덤 접근 속도** | `O(1)` (빠름) | `O(1)` (빠름) | `O(n)` (느림) |
| **삽입/삭제 속도** | `O(n)` (느림) | `O(n)` (중간 삽입/삭제 느림) | `O(1)` (빠름, 특정 노드 기준) |
| **초기 크기 설정 필요** | 필요 | 필요 없음 (자동 조정) | 필요 없음 |
| **데이터 구조** | 연속된 메모리 | 동적 크기 배열 | 이중 연결 리스트 |”

- ArrayList
  - 연속된 메모리 공간에 저장되므로 index를 이용한 빠른 랜덤 접근이 가능함.
  - 중간에 요소를 삽입/삭제하면 뒤쪽 요소를 모두 이동해야 하므로 O(n) 시간이 걸림.
- LinkedList
  - 각 요소가 **노드(Node)**로 존재하고, 앞뒤 노드와 포인터(참조)로 연결되므로 처음부터 하나씩 탐색해야 함.
  - 포인터(참조)만 변경하면 되므로 특정 위치만 알고 있다면 O(1) 시간 안에 삽입/삭제 가능.
